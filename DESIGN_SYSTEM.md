# Struq Voice: design system

**Velden Linen Forest.** A warm linen page, deep forest ink, one terracotta accent.

This document is binding. It is not a mood board and it is not a suggestion. If an interface
decision is not covered here, decide it by extending the logic below rather than by importing a
convention from somewhere else.

Ready-to-use token layer: [`assets/theme.css`](assets/theme.css).

---

## 1. The two rules

Everything else in this document is downstream of these.

**Rule 1. Accent is for primary actions and moments of emphasis. Nothing else.**
One primary action per view. The record control, the state of a live capture, the single
destructive confirm. Not section headers, not icons, not active nav items, not borders on things
that merely exist. An interface where everything is accented has no emphasis at all, only noise.

**Rule 2. Interaction states are generated by brightness. Only brightness.**
Hover, active and pressed move lightness. Hue and chroma are frozen. There is never a second
colour hiding inside a state change. In OKLCH this is literally editing one number, which is the
point: it is impossible to drift.

```css
--color-accent-solid:        oklch(0.535 0.12 45);
--color-accent-solid-hover:  oklch(0.495 0.12 45);   /* L down 0.04 */
--color-accent-solid-active: oklch(0.455 0.12 45);   /* L down 0.04 */
```

On a light interface, hover moves **darker**. Do not invent a lighter hover for a light theme.

## 2. Why this palette works, and how not to break it

The palette has a structural quirk worth understanding before you build with it:
**surfaces are lighter than the background.**

```
oklch(0.985)  surface     cards, panels, rows
oklch(0.967)  background  the page itself
oklch(0.942)  bg-sunken   inputs, wells, code blocks
```

This inverts the habit most people carry over from dark interfaces, where panels sit darker than
the canvas. Here it is paper on linen: cards catch the light, wells recede into it. Get this
backwards and the whole thing reads as a bad Bootstrap theme.

The second thing to protect is the **temperature split**. The page is warm (hue 95, yellow). The
ink is cool (hue 150, green). That tension is the entire character. Two failure modes destroy it:

- **Neutral grey borders and text.** A `#e5e5e5` hairline on a warm page reads as grey dirt. Every
  border here is forest-tinted. Every muted text value keeps its green cast.
- **Pure black or pure white.** Neither appears anywhere. Text is `oklch(0.30 0.025 150)`, not
  `#000`. The lightest surface is `oklch(0.985)`, not `#fff`.

### Contrast, already verified

Approximate WCAG ratios against `--color-bg`. Anything carrying body text clears AA.

| Token | Ratio | Safe for |
|---|---:|---|
| `--color-text` | ~12.4:1 | anything |
| `--color-text-secondary` | ~7.1:1 | anything |
| `--color-text-muted` | ~5.0:1 | body text and smaller |
| `--color-accent-text` | ~5.45:1 | accent-coloured text |
| `--color-accent` | ~3.9:1 | **fills, rings, indicators only. Not text.** |
| `--color-text-inverse` on `--color-accent-solid` | ~4.96:1 | filled button labels |

The given accent at `oklch(0.58 0.12 45)` is not safe behind white body text (~4.1:1, short of
AA). That is why `--color-accent-solid` exists at L 0.535. It is the same hue and the same chroma,
derived purely by brightness, so Rule 2 holds and the accent still reads as the accent.

## 3. Type

**Instrument Sans** for interface. **Instrument Serif** for prose and identity. **IBM Plex Mono**
for anything numeric.

The two Instrument faces are by the same foundry and are drawn to sit together. That is why they
are paired here rather than assembled from two unrelated families off a list.

**Inter is deliberately absent.** It is the house font of software that looks like every other
piece of software, and using it here would undo the palette's work in a single line.

### Where the serif goes

Not everywhere. Three places, and they are the places where this app is not a utility:

1. The wordmark.
2. Empty-state and first-run headlines.
3. **The transcript itself**, in the History reader view, at `--text-lg` with `--leading-prose`.

That third one is the argument. A dictation app's output is writing. Setting a person's words in a
reading face, on linen, is the most legible statement this interface can make about what it is
for. Everywhere the transcript is chrome rather than content (list previews, the overlay's
confirmation flash) it stays in the sans.

### Scale

Fixed, not fluid, except the display size. A desktop app at a known window size does not benefit
from viewport-scaled body text; it benefits from predictability.

| Token | Size | Use |
|---|---:|---|
| `--text-2xs` | 11px | keyboard hints, unit labels |
| `--text-xs` | 12px | metadata, column headers |
| `--text-sm` | 13px | **UI default** |
| `--text-base` | 15px | body, settings descriptions |
| `--text-lg` | 17px | transcript reading size |
| `--text-xl` | 22px | section titles |
| `--text-2xl` | 28px | view titles |
| `--text-display` | fluid 32 to 48px | wordmark, first-run only |

Rules:

- **Three sizes per view, maximum.** Four is a smell. Five means the hierarchy has failed and you
  are compensating with size instead of space and weight.
- **Weight before size.** Reach for 600 before you reach for a bigger token.
- **Negative tracking above 22px only.** Large type has too much air by default; small type needs
  all of it.
- **Tabular numerals on anything that changes.** Timers, costs, realtime factors, durations. The
  `[data-numeric]` attribute in `theme.css` handles this. A layout that twitches while a timer
  counts is a bug.
- **Measure caps at 68 characters** for transcript prose. Below that it is choppy, above it the
  eye loses the line.

## 4. Space

A 4px base, exposed as `--spacing`. Tailwind v4 derives the whole scale from it.

**If a value is not on the scale it is a mistake, not a nuance.** No `padding: 13px`. No
`margin-top: 7px`. The one exception is optical correction on a specific glyph or icon, which must
carry a comment saying so.

Composition defaults:

| Context | Value |
|---|---|
| Icon to adjacent label | 8px |
| Inside a control (button, input) | 8px vertical, 12px horizontal |
| Between related controls | 8px |
| Between fields in a group | 12px |
| Between groups in a panel | 24px |
| Panel inset | 20px |
| Between sections in a view | 32px |
| View gutter | 24px |

**Space carries hierarchy before borders do.** Reach for a gap before you reach for a divider. Most
interfaces are over-ruled: they draw a line where 24px of air would have said the same thing more
quietly.

## 5. Elevation

Depth is built from **surface steps and hairlines**, not shadow stacks.

```
bg-sunken   recessed: inputs, wells, code blocks
bg          the page
surface     raised: cards, rows, panels
```

Exactly **two shadows exist**, and both are reserved for surfaces that genuinely float above the
operating system:

- `--shadow-float`: the capture overlay pill.
- `--shadow-lift`: the command palette, dropdown menus, popovers.

An in-app card gets a hairline border and a lighter surface. It does not get a shadow. Stacked
`shadow-lg` on everything is the most reliable tell of an interface that was assembled rather than
designed.

Note that both shadows are tinted with the forest hue at low alpha, never neutral black. Black
shadows on a warm page turn grey and muddy.

## 6. Motion

Motion clarifies causality. It says *this came from there* and *that is still working*. It never
decorates.

- **Springs for anything spatial.** Position, scale, anything the eye tracks through space.
  `motion`'s `type: 'spring', stiffness: 400, damping: 32` is the house default.
- **Cubic-bezier for anything tonal.** Colour, opacity, borders. `--ease-out-quart` at
  `--duration-fast`.
- **Nothing exceeds 240ms** except the waveform, which is continuous rather than transitional.
- **Entrances animate. Exits mostly do not.** A panel that fades out slowly is a panel in the way.
- **Never animate `width`, `height`, `top` or `left`.** Transform and opacity only. The waveform
  must hold 60fps while a 0.6B parameter model saturates eight cores, and layout animation will not.
- **`prefers-reduced-motion` removes motion, not layout.** Already handled in `theme.css`. Verify
  it in the e2e suite rather than assuming it.

## 7. Components

Take the accessibility, replace the skin. See section 9 for the shadcn rule.

### Button

Four variants. There is no fifth.

| Variant | Surface | Text | Border | Use |
|---|---|---|---|---|
| `primary` | `--color-accent-solid` | `--color-text-inverse` | none | **One per view.** |
| `secondary` | `--color-surface` | `--color-text` | `--color-border` | Everything ordinary. |
| `ghost` | transparent | `--color-text-secondary` | none | Toolbars, row actions. |
| `danger` | transparent | `--color-danger` | `--color-danger` | Destructive confirms. |

Height 32px default, 28px compact, 40px for the one primary action in a first-run step. Radius
`--radius-md`. Hover moves lightness by 0.04, active by another 0.04. Disabled drops opacity to
0.45 and never changes hue.

A button label is a **verb**. "Download model", not "Model". Never "Click here". Never "Submit".

### Input

`--color-bg-sunken` fill, `--color-border` hairline, no shadow. Focus swaps the border to
`--color-border-focus` and adds the global focus ring. Placeholder is `--color-text-muted` and
describes the *format*, never repeats the label.

### Card and list row

`--color-surface`, `--radius-lg`, 1px `--color-border`, no shadow. Row hover goes to
`--color-surface-hover`. Selected rows take a 2px `--color-accent` left edge, not a full accent
fill: the accent marks the selection, it does not become the row.

### Badge

Small caps, `--text-2xs`, `--tracking-wide`, `--radius-sm`, soft-token background
(`--color-accent-soft` and friends) with the matching solid token as text. Engine names, cloud/local
markers, cost indicators.

### The capture overlay pill

The one surface that must be beautiful, because it is the only one seen daily.

360x88, bottom-centre of the display containing the cursor, 24px above the work area.
`--color-surface` at full opacity (not glass, not blurred), `--radius-pill`, 1px `--color-border`,
`--shadow-float`.

| State | Treatment |
|---|---|
| `listening` | Canvas waveform, 32 bars, `--color-state-listening`. Elapsed timer in mono. |
| `transcribing` | Bars collapse to a centre line, a shimmer sweeps once. Engine name in small caps. |
| `delivering` | Checkmark draws in `--color-state-delivered`. First ~40 chars fade in beneath. Auto-dismiss 900ms. |
| `error` | Border to `--color-state-error`. One actionable line. "Copy anyway" if text exists. |

The waveform is `<canvas>`, driven by `requestAnimationFrame`, transform-only. Levels arrive at
60Hz and are interpolated between frames so the bars read as smooth rather than stepped.

## 8. Anti-patterns

These are the tells. Each one is individually forgivable and collectively fatal. **None of them
ship.**

**Visual**

- Gradient text. Gradient buttons. Mesh gradients. Animated gradients.
- Glassmorphism, `backdrop-blur` cards, frosted panels.
- The purple-to-blue "AI product" palette. We have a palette.
- Glows, pulsing halos, neon rings.
- Stacked `shadow-lg` / `shadow-xl` on ordinary cards.
- `rounded-full` on everything. The pill radius belongs to the overlay and to badges.
- Mixed radii inside one composition.
- Pure `#000` or `#fff`. Neither exists in this system.
- Neutral grey borders on the warm page.

**Structural**

- Three-column feature grids of icon, heading, two lines of filler.
- Centred hero paragraphs in a utility application.
- Decorative illustrations in empty states.
- Sparkle icons. Robot icons. Anything signalling "there is AI in here".
- Emoji anywhere in the interface.
- Icons that repeat their own label. An icon must carry meaning the label cannot.
- A settings page that is one long undifferentiated column of switches.

**Copy**

- "Oops!", "Something went wrong", "An error occurred". Every error names the cause **and** the
  fix. "Model not downloaded. Download Parakeet v3 (660MB)." is an error message. "Transcription
  failed" is not.
- Exclamation marks.
- "Powered by", "Supercharge", "Seamlessly", "Effortlessly", "Unlock".
- Placeholder or lorem copy surviving into a commit.
- Em dashes and en dashes. Restructure the sentence. See the repo rules.

**Behavioural**

- A spinner where a skeleton or a real progress number would do. Downloads report bytes and rate.
- Toasts for things the user can already see happen.
- Confirmation dialogs for reversible actions.
- Disabled buttons with no explanation of what would enable them.

## 9. How to use shadcn/ui here

shadcn is in this stack for **behaviour, not appearance**.

What it is genuinely good at, and what would be foolish to rewrite: Radix's focus management,
keyboard navigation, roving tabindex, portal and dismissal semantics, ARIA wiring, scroll locking.
Accessible menus and dialogs are hard, and these are correct.

What must be replaced wholesale: the visual layer. The default shadcn skin is a neutral grey
Tailwind theme, and it is the single most recognisable look in current software. Shipping it
unmodified is exactly the outcome this document exists to prevent.

**The workflow:**

1. `pnpm dlx shadcn@latest add dialog dropdown-menu select switch tabs tooltip scroll-area`
2. The component lands in `src/renderer/components/ui/`. **You own it now.** It is your file.
3. Strip every default class. Rebuild the appearance from the tokens in `theme.css`.
4. Delete variants you will not use. A `Button` with six variants when the system defines four is
   four unused code paths and one broken rule.
5. Keep every `data-*` attribute, `aria-*` binding and ref forward exactly as generated. That is
   the part you came for.

Configure `components.json` with `"config": ""` for the Tailwind v4 Vite plugin setup, `"css"`
pointing at the renderer stylesheet, and `"baseColor"` set to `neutral` (it only seeds the initial
values, all of which you are about to replace).

**Do not** run `shadcn add` and move on. A generated component that has not been restyled is not
finished work.

## 10. Self-review

Before any UI commit, answer these. An honest "no" anywhere means it is not done.

1. Is there exactly one accent-coloured primary action in this view?
2. Does every hover state differ from its base by lightness alone?
3. Are all values on the 4px scale?
4. Three type sizes or fewer?
5. Are surfaces lighter than the background, and wells darker?
6. Any neutral greys, pure black, or pure white? (Must be none.)
7. Any shadow outside the overlay, palette, and popovers?
8. Does every icon carry meaning its label cannot?
9. Does every error name a cause and a fix?
10. Zero em dashes and en dashes?
11. Does it hold 60fps with a model running?
12. Does `prefers-reduced-motion` remove motion without breaking layout?

---

## 11. Deferred

**Dark mode.** The supplied palette is light and the app ships light-only in v1. A dark variant is
not a matter of inverting lightness values; the warm/cool tension has to be re-derived from
scratch or it collapses into ordinary dark grey. `color-scheme: light` is declared explicitly so
the OS does not attempt it on our behalf. Revisit once the light system has settled in daily use.
